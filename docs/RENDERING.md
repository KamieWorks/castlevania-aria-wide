# 逆向基线与渲染约定

## 身份与边界

目标为 Steam build 7039365 的 PE32 game.exe：
404e78ade8b92fe3a89aa2ed3e7de8bde3545d694e669835a81145f5e026e6bb。
所有以下主机地址均为该构建的 RVA。正式代码先校验 SHA-256 和各入口指令，
未知 EXE 返回 -10，不向未知布局写入挂钩。宽屏仅绑定 ROM code A2C 的晓月。

合集外壳已支持宽屏；实际 GBA 光栅是 240×160 RGB555。
扩大地图与 OBJ 绘制后输出 288×162，上下各一行空白，保持像素比例。
只拉伸最终 D3D9 纹理不能增加可见世界。

## 主机入口与数据

| RVA | 调用约定/作用 |
| --- | --- |
| 0x47680 | fastcall(PPU,y)，扫描行 |
| 0x47710 | fastcall(PPU,bitmap)，原生呈现 |
| 0x39ab0 | cdecl(context,out)，视频尺寸 |
| 0x406c0 / 0x40610 | fastcall(context)，快照保存/载入 |
| 0x39f60 | cdecl(context)，core 销毁 |
| 0x433a0 / 0x443e0 | 原生文本 BG / OBJ 渲染 |
| 0x43140 | 窗口遮罩重建 |
| 0x45160 / 0x45810 | mode 0 / mode 1 合成 |

context +0x138 为 PPU 指针；+0x150 为 EWRAM，+0x40150 为 IWRAM，
+0x48150 为 SRAM，+0x1a0558/+0x1a055c 为 ROM 指针/大小。
PPU 大小 0x5f4b8；VRAM +0，OAM +0x20000，调色板 +0x20400，IO +0x20800。
缓存 BG control +0x21ff0，BG scroll +0x21ff8（每层四字节），flags +0x22048。
三帧 RGB555 环形像素 +0x22064，每帧 0x14000，行跨度 256 像素；索引 +0x5e064。
当前行中间值 +0x20c00，每像素 20 字节，BG0/1/2/3/OBJ 各 U32。

## 视口与 BG 视差

主地图元数据在 EWRAM+a094；x16.16 在 +a098，整数视图在 +a09a。
其他 BG info 位于 a078+bg*28。不能用未来 RAM 相机直接裁切当前光栅。
扫描线 0 用锁存 BG1 HOFS（PPU+0x21ffc）解包为当前相机页，正常差值只接受 ±8。

令 C 为当前光栅相机，W 为房间宽度：

- Cw = clamp(C-24, 0, W-288)
- L = C-Cw，范围 0..48，原生 240 像素放在输出 x=L

新增视野随房间边界向内分配。固定单屏房间默认退出扩展；可选装饰实现保留，
不会改变碰撞或敌人逻辑范围。BG 图块新增列只在 PPU 私有副本重建。

BG2/BG3 保留原生固定、半速、倍速和尺寸拟合等倍率。先去除 RAM 提前一步的
相机贡献，使分数位置与当前光栅同相，再组合取整；不能分别取整补偿值。
原生 HBlank 波动和时间滚动仍由每扫描行寄存器驱动。
mode 1 的仿射 BG2 同时移动重载/累积坐标，不能按普通文本 BG 修补。

## HUD 与原生光栅流水线

BG0 的健康条和 palette-E 通知分开合成：血条左上、道具/钱左下、敌人信息右下、
魂短通知右上；居中魂说明框保持居中。不要把整行 BG0 一起移动。
HP 数字仅匹配原生 palette7、tiles 0x80..0x89、y6、x6..26 的五像素步距。

原生 scan(y) 使用预计算的当前 OBJ 行，随后准备 y+1。中心克隆继承该当前行，
不能重新调用 OBJ 把它错移一行。临时 cached OAM 的改动只围绕同步原生扫描调用，
之后恢复，guest 执行时看见原始状态。精确空闲 OAM (0,0x1e0,0) 必须排除，
避免扩展左侧露出原来藏在 x=-32 的空对象。

## 半透明云

area 0 / room 10 月亮前的紫云是 OBJ，不是 BG2/BG3。
EWRAM entityData=0x4e4，stride 0x84，224 个槽位。x/y16.16 为 +0x40/+0x44；
原生云 controller 在 JP 0x0804db39、US 参考 sub_0804F504，先加自主漂移，
再减主相机 x/y velocity /12。原生自主 x 漂移可为 128/65536 像素每更新。

同 paletteB/priority3 的鸟不是云。正式代码同时验证控制器 Thumb 指令签名、
阶段/类型、draw 指针，以及匹配实体位置的非仿射半透明 32×16 OAM 片段。
VBlank 呈现时锁存实体分数位置，它属于下一帧 OAM；扫描线 0 的 RAM 可能已领先。

令 delta=L-24，云原生屏幕坐标 x 为 16.16；每片段的显示补偿为：

floor((12*x - 11*delta*65536)/(12*65536)) - floor(x/65536)

它保留自主漂移，同时使前景镜头钳位期间的云不再额外被拖动约 22 像素。
四个实体对应六个原生片段；不能把同调色板的全部精灵一并移动。

## 保存、倒带与销毁

ARIA-WIDE-1 扩展记录版本 9，共 95388 字节，保存两侧三帧各 48×160 的混帧历史，
以及云锁存/128 项 OAM 补偿。中央原生状态继续由 core 保存。
同版往返需逐字节相等；旧版记录按缺少扩展历史回退并重新预热。
销毁/换 core 时清除 PPU/context 绑定，不能沿用已释放的指针。
保留 MovieStreamSoundPlayer 子任务别名清理与 state-list 双重释放防护，详见代码。
